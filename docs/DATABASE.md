# База данных FitBook

Проект использует PostgreSQL в Supabase. Рабочая схема уже развёрнута в проекте `fitbook-final`.

## Таблицы

- `profiles` - профиль пользователя и роль `user/admin`.
- `trainers` - тренеры и специализация.
- `sessions` - расписание занятий, вместимость и число занятых мест.
- `bookings` - записи пользователей на занятия.
- `booking_status_history` - история изменения статусов записей.

Системная таблица `auth.users` используется Supabase Auth.

## Связи

- `auth.users 1:1 profiles`.
- `trainers 1:N sessions`.
- `profiles 1:N bookings`.
- `sessions 1:N bookings`.
- `bookings 1:N booking_status_history`.

## Проверки лабораторной

В базе проверены запросы с `WHERE`, `ORDER BY`, `JOIN`, `COUNT` и `GROUP BY`. Для административной панели рассчитываются количество пользователей, количество занятий, количество активных записей, посещения, отмены и средняя заполненность занятий.

## Бизнес-правила

Критичные операции выполняются RPC-функциями PostgreSQL. База блокирует запись при отсутствии мест, повторную активную запись на то же занятие, пересечение времени, запись на прошедшее или отменённое занятие. Пользовательская отмена ограничена правилом двух часов.

## RLS

Row Level Security включён на всех пяти прикладных таблицах. Обычный пользователь видит только собственные записи и историю, а административные операции доступны только роли `admin`.
